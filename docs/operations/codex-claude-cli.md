# Codex and Claude CLI runner support

The canonical harness registry enables Copilot, Codex CLI and Claude CLI. All three use the existing runner admission, credential leases, exact sandbox binding, attempt fences and cleanup. Coven Agents drives their CLIs; it does not add a direct model-provider adapter. The new image generation is `coven-agents-copilot-3`; the historical name prefix is retained for configuration compatibility, and the image now includes all three pinned executables. Provisioning, deployment and real provider execution are separate operator actions. Existing immutable generation-2 snapshots are not upgraded in place.

| Runtime | Package pin | Credential supplied to the existing encrypted harness credential store | Structured output |
| --- | --- | --- | --- |
| `copilot` | `@github/copilot@1.0.80` | Existing Copilot CLI credential | `--output-format json` |
| `codex` | `@openai/codex@0.152.1` | ChatGPT CLI `auth.json`, serialized as the credential value | `exec --json` |
| `claude` | `@anthropic-ai/claude-code@2.1.258` | Claude CLI OAuth token | `--print --output-format stream-json --verbose` |

Codex requires `auth_mode: "chatgpt"`, nonempty `id_token`, `access_token`, `refresh_token` and `account_id` under `tokens`, and an absent or null `OPENAI_API_KEY`. API-key authentication is refused. Do not paste an auth file into an issue, command line, log or repository. Use the existing private credential-management flow. The staging environment name `COVEN_CODEX_AUTH_JSON` is internal to the runner and is not a Codex CLI option. The value is transferred only through the SDK's per-call environment, written to a mode-0600 attempt file, then moved into the attempt's isolated `CODEX_HOME/auth.json`. It is never embedded in the launch command. Only the supported auth fields are staged, including a validated optional last_refresh timestamp; unknown private fields are omitted. Each distinct token/account value is registered in the existing bounded encrypted attempt-redaction envelope. Pretty-printed JSON and an aggregate auth file larger than 4096 bytes are supported when each private value fits the existing codec and evidence bounds. Individual values above 4096 UTF-8 bytes, control-bearing tokens or an over-limit aggregate redaction envelope are refused at credential save and again before provider effects. The raw JSON is not registered as one secret, so formatting and total JSON size cannot silently prevent launch. Cleanup and stale-credential sweeping remove both the staged file and the exact attempt auth file; the existing sandbox-reset and ambiguity fences still apply.

Claude receives its caller-owned `CLAUDE_CODE_OAUTH_TOKEN` through the existing staging boundary and an isolated `CLAUDE_CONFIG_DIR`. It does not inherit another run's sign-in directory. After canonical unrestricted authorization, the Daytona-only launch sets IS_SANDBOX=1 for the pinned CLI's deliberate-sandbox root prerequisite and DISABLE_AUTOUPDATER=1 to preserve the native package pin. These settings grant no separate execution authority; unsupported restricted modes still refuse before this launch path. The exact pinned binary supports both settings; native UID-0 execution and target-sandbox behavior remain separate operator evidence. Provider API-key variables are unset for every launched CLI. The hermetic test environment also clears Codex and Claude configuration/authentication variables, including the retired `CODEX_API_KEY` path. No production credential or authenticated model call is required for local tests.

Codex and Claude are enabled for the existing explicitly authorized unrestricted sandbox mode. They refuse `github_only`, `workspace_read`, `workspace_write` and brokered GitHub-tool requests before provider preparation or credential staging. No unsupported restricted mode falls back to a dangerous bypass flag. Copilot retains its existing restricted implementation. The unrestricted CLIs retain their existing sandbox bypass flags because the canonical lifecycle owner separately authorizes that mode inside its sandbox; this is not permission to run them unsandboxed on an operator host.

Codex exec item messages, command/MCP results, successful file changes and terminal turn results are translated into the existing normalized event schema. Claude assistant messages, tool calls/results and final result frames use the same schema. Unknown vendor frames are ignored; malformed recognized shapes are refused. Tool errors remain errors, failed patches are not reported as successful file changes, and token counts are not misreported as Copilot premium requests. Log reconciliation selects the frozen run's harness rather than assuming Copilot. Codex and Claude terminal frames wait for the provider process to settle; a later nonzero process exit remains a failure, and the delivery cursor retains an early terminal frame without replaying prior events. Process exit codes remain unknown until observed. Existing timestamp validation, redaction, chunk assembly and evidence bounds remain canonical.

Protocol references: [Codex exec event definitions](https://github.com/openai/codex/blob/main/sdk/typescript/src/events.ts), [Codex item definitions](https://github.com/openai/codex/blob/main/sdk/typescript/src/items.ts), and [Claude programmatic CLI documentation](https://code.claude.com/docs/en/headless). The exact pinned packages were installed in isolated local npm caches and their help/version commands exited successfully: Codex 0.152.1 and Claude Code 2.1.258. Claude required its normal native-binary postinstall; an initial installation with lifecycle scripts disabled could not launch, and that first failure is retained. No authenticated task was run. The PR checkpoint records the exact source revision and commands. Synthetic event streams establish local translation behavior; installed help proves the flags exist, not authentication, remote deployment or a successful model run.

Before deployment, an operator must provision and select the new immutable snapshot through the existing approved release process, verify the installed binaries in the target sandbox, configure the required owner egress policy for the selected CLI, and authorize any real run separately. Castles' accepted snapshot/profile remains unchanged by this companion producer change. The #322 metadata consumer uses its separately pinned producer and does not infer installed Codex/Claude support from source policy. Independent review, maintainer acceptance and live-provider qualification remain pending until explicitly recorded.
